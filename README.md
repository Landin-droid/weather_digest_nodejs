# Weather Digest

Консольная утилита на Node.js для получения прогноза погоды по названию города через открытый API [Open-Meteo](https://open-meteo.com/). Утилита принимает один или несколько городов, получает координаты и прогноз, выводит результат в терминал в читаемом виде и сохраняет отчёт в файл.

## Требования к окружению

- Node.js версии 20 и выше (используется встроенный `fetch`, `AbortController`, `node:util.parseArgs`, `node:test`)
- Доступ в интернет для первого запроса по каждому городу (повторные запросы за тот же день используют кэш)

## Установка

```bash
git clone https://github.com/Landin-droid/weather_digest_nodejs.git
cd weather_digest_nodejs
npm install
cp .env.example .env
```

## Переменные окружения

Настраиваемые параметры вынесены в переменные окружения. Пример значений — в `.env.example`.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `WEATHER_API_TIMEOUT_MS` | Таймаут сетевого запроса (мс), реализован через `AbortController` | `5000` |
| `REPORTS_DIR` | Каталог для сохранения и чтения отчётов | `reports` |
| `GEOCODING_BASE_URL` | Базовый URL API геокодинга (Open-Meteo) | `https://geocoding-api.open-meteo.com/v1/search` |
| `FORECAST_BASE_URL` | Базовый URL API прогноза погоды (Open-Meteo) | `https://api.open-meteo.com/v1/forecast` |

Дополнительно, при запуске в Docker, параметры запуска (`--city`, `--days`, `--no-cache`) можно передавать через переменные окружения `CITY`, `DAYS`, `NO_CACHE` — см. раздел [Запуск в Docker](#запуск-в-docker).

## Запуск

```bash
# Один город, 3 дня (значение по умолчанию)
node src/index.js --city "Томск"

# Несколько городов через запятую
node src/index.js --city "Томск, Красноярск, Москва"

# Указать количество дней прогноза (допустимо 1-7)
node src/index.js --city "Томск" --days 7

# Принудительно обновить данные, игнорируя кэш за сегодняшний день
node src/index.js --city "Томск" --no-cache
```

| Параметр | Обязательный | Описание |
|---|---|---|
| `--city` | да | Название города или несколько городов через запятую |
| `--days` | нет | Количество дней прогноза, от 1 до 7 включительно, по умолчанию `3` |
| `--no-cache` | нет | Принудительный запрос к API, игнорируя сохранённый на сегодня отчёт |

## Пример вывода

```
🚩 Томск, Россия (56.50049, 84.98216)
   Дата         Мин, °C   Макс, °C   Осадки, мм
   2026-09-13    12.4        25.8         0.1
   2026-09-14    14.5        21.6         2.3
   2026-09-15    11.6        17.7         0.2
```

Если данные взяты из ранее сохранённого отчёта за сегодня, под заголовком выводится пометка `(данные из кэша)`.

## Обрабатываемые ошибки

| Ситуация | Поведение |
|---|---|
| Отсутствует `--city` | Сообщение об ошибке аргументов, код выхода `1` |
| Некорректный `--days` (не число или вне диапазона 1-7) | Сообщение об ошибке аргументов, код выхода `1` |
| Город не найден (пустой результат геокодинга) | Ошибка выводится только по этому городу, остальные города обрабатываются дальше |
| Ответ API со статусом 4xx | Понятное сообщение об ошибке запроса, обработка остальных городов продолжается |
| Ответ API со статусом 5xx | Понятное сообщение об ошибке сервера, обработка остальных городов продолжается |
| Нет сети | Сообщение о сетевой ошибке |
| Превышен таймаут запроса | Сообщение о таймауте (настраивается через `WEATHER_API_TIMEOUT_MS`) |
| Некорректный JSON в ответе | Сообщение об ошибке разбора данных |

Все ошибки выводятся пользователю понятным текстом без стек-трейса. Необработанные исключения и unhandled promise rejection перехватываются на уровне всего процесса.

**Код завершения процесса:**

| Код | Значение |
|---|---|
| `0` | Все города обработаны успешно |
| `1` | Ошибка аргументов или хотя бы один город завершился с ошибкой |

## Структура проекта

```
weather_digest_nodejs/
├── src/
│   ├── index.js              # точка входа: разбор аргументов, запуск, обработка ошибок
│   ├── api/
│   │   ├── httpClient.js     # общий HTTP-клиент: fetch, таймаут (AbortController), статусы
│   │   ├── geocoding.js      # запрос геокодинга (определяет координаты города)
│   │   └── forecast.js       # запрос прогноза погоды по координатам
│   ├── services/
│   │   └── weatherService.js # бизнес-логика: связывает геокодинг, прогноз и кэш
│   ├── storage/
│   │   └── reportStorage.js  # чтение/запись отчётов в reports/, работа с кэшем
│   ├── tests/
|   |   ├── forecast.test.js   # юнит-тесты API прогноза по координатам
│   │   └── geocoding.test.js  # юнит-тесты API определения координат города
│   └── format/
│       └── output.js         # форматирование вывода в консоль
├── public/
│   └── report-viewer.html    # HTML-страница для просмотра сохранённого отчёта
├── docs/
│   └── postman/              # экспортированная коллекция и окружение Postman
├── reports/                  # сохранённые отчёты (в git не попадает)
├── Dockerfile                # сборка образа для запуска утилиты в контейнер
├── .dockerignore
├── eslint.config.js          # конфигурация ESLint
├── .prettierrc / .prettierignore
├── .env.example
├── .gitignore
├── README.md
└── package.json
```

**Разделение по модулям:** `api/` отвечает только за сетевые запросы, `services/` связывает шаги обработки (город → координаты → прогноз → кэш), `storage/` — за файловую систему, `tests/`— за тестирование, `format/` — за вывод в консоль, `index.js` — слой для разбора аргументов и запуска.

## Тестирование

Базовые тесты реализованы через встроенный тест-раннер `node:test` (без сторонних библиотек) и проверяют разбор ответа API и обработку ошибочных сценариев (пустой результат геокодинга, ошибочный статус ответа).

```bash
npm test
```

## Тестирование API в Postman

Коллекция с обоими используемыми запросами (геокодинг и прогноз), переменные окружения и сохранённые примеры ответов (успешный, «город не найден», ошибка с указанием кода статуса) находятся в `docs/postman/`. Импортируйте оба файла в Postman для проверки запросов вручную.

## Запуск в Docker

```bash
# Сборка образа
docker build -t weather-digest .

# Запуск, где параметры передаются через переменные окружения
docker run --rm -e CITY="Томск, Москва" -e DAYS=5 weather-digest

# Запуск с сохранением кэша между перезапусками контейнера
docker run --rm -e CITY="Томск" -v ./reports:/app/reports weather-digest
```

Параметры `--city`/`--days`/`--no-cache` передаются в контейнер через переменные окружения `CITY`, `DAYS`, `NO_CACHE` — это стандартный способ конфигурировать запуск контейнера. При запуске без Docker используются обычные CLI-флаги, как описано в разделе [Запуск](#запуск).

## Просмотр отчёта в браузере

Откройте `public/report-viewer.html` в браузере и выберите файл отчёта из папки `reports/` — страница выведет город, страну и таблицу прогноза по дням средствами DOM API, без сторонних библиотек.
